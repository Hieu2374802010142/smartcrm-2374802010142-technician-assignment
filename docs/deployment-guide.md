## 1. Overview

SmartCRM L04 is a web-based warranty management application developed using Python, FastAPI, and SQLite.

The system allows center managers to view unassigned warranty tickets, assign technicians, and schedule appointments. It also provides authentication and authorization to protect management functions.

This document explains how to install, configure, deploy, and verify SmartCRM using Docker and Docker Compose.

## 2. System Requirements

The following software is required:

- Docker Desktop with Docker Compose support
- Git
- A web browser such as Google Chrome
- Python 3.12 and pytest (optional, for running tests locally)

The application uses the following technologies:

- **Backend:** Python 3.12 and FastAPI
- **Frontend:** HTML, CSS, and JavaScript
- **Database:** SQLite
- **Containerization:** Docker and Docker Compose
- **Web server:** Uvicorn

## 3. Installation and Setup

### Step 1: Clone the repository

Open Terminal and run:

```bash
git clone https://github.com/Hieu2374802010142/smartcrm-2374802010142-technician-assignment.git
```

Navigate to the project directory:

```bash
cd smartcrm-2374802010142-technician-assignment
```

### Step 2: Configure environment variables

Create a `.env` file in the project root.

The application requires the following administrator authentication settings:

```env
SMARTCRM_ADMIN_USER=manager
SMARTCRM_ADMIN_PASSWORD_SALT=<generated-salt>
SMARTCRM_ADMIN_PASSWORD_HASH=<generated-password-hash>
```

Replace the placeholder values with valid credentials generated by the project's administrator setup procedure.

Do not use plain-text passwords as password hashes. Never commit `.env`, passwords, or other secrets to GitHub.

Docker Compose reads the `.env` file when starting the application.

### Step 3: Build and start Docker containers

Run:

```bash
docker compose up -d --build
```

Docker Compose builds the SmartCRM image, creates the application container, and starts the FastAPI server.

The container uses port 8000 and stores its SQLite database in a persistent Docker volume.

### Step 4: Verify the container

Check the running services:

```bash
docker compose ps
```

View application logs:

```bash
docker compose logs --tail=50
```

The application should start without errors and become healthy after initialization.

## 5. Database Initialization and Persistence

SmartCRM uses SQLite for data storage.

During Docker startup, the application executes its database seed procedure before starting Uvicorn.

The SQLite database is stored at:

```text
/data/smartcrm.db
```

Docker Compose uses a named volume to preserve database data when the container is recreated.

To stop the application without deleting stored data:

```bash
docker compose down
```

To restart the application:

```bash
docker compose up -d
```

**Important:** Do not use `docker compose down -v` unless you intentionally want to remove the database volume and its stored data.

## 7. Security Considerations

SmartCRM includes the following security measures:

- Manager authentication is required for protected management APIs.
- Frontend requests include an Authorization Bearer token.
- Administrator password credentials are configured using a salt and password hash.
- Sensitive environment variables are stored outside the Docker image.
- `.dockerignore` excludes unnecessary and sensitive files from the Docker build context.
- The application port is bound to the local host for local deployment.
- Appointment scheduling includes validation to prevent invalid time ranges and overlapping appointments.

Additional security checks should be recorded in the project's security checklist.

## 8. Troubleshooting

### Container does not start

Check the container logs:

```bash
docker compose logs --tail=100
```

Review the error messages and verify the environment configuration.

### Port 8000 is already in use

Check whether another application is using port 8000. Stop the conflicting service before restarting Docker Compose.

### Login fails

Verify that the administrator environment variables are configured correctly.

Check the browser's network requests and Docker logs for authentication errors.

### Dashboard displays an authentication error

Ensure that the frontend sends the Bearer token when requesting protected APIs.

Rebuild the container after changing frontend code:

```bash
docker compose up -d --build
```

Refresh the browser to load the updated frontend.

### Database data is missing

Check that the Docker named volume exists and that the database path is correctly configured.

Avoid deleting the persistent volume when restarting the application.
